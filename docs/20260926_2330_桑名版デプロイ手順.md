# みらい議会＠桑名市 デプロイ手順（Supabase + Vercel）

本家と同じ構成（Supabase = DB/認証、Vercel = web・admin の2プロジェクト、Vercel AI Gateway = AI呼び出し）で公開する手順。
GitHub Actions の `deploy.yml` が「`main` への push → DB マイグレーション → Vercel デプロイ」を自動で行う。

## 全体像

| 役割 | サービス | 備考 |
|---|---|---|
| 公開サイト（`web/`） | Vercel プロジェクト①（Root Directory: `web`） | 市民向け |
| 管理画面（`admin/`） | Vercel プロジェクト②（Root Directory: `admin`） | 議案の登録・AI生成など |
| DB・認証 | Supabase プロジェクト（リージョン: Tokyo 推奨） | マイグレーションは `supabase/migrations` |
| AI | Vercel AI Gateway | AIチャットは `anthropic/claude-haiku-4.5` |
| トピック分析（任意） | Google Cloud Run（`worker/`） | 使わない場合は不要。`infra/cloud-run/README.md` 参照 |

## 1. GitHub に公開リポジトリを作る

1. GitHub で新しい **公開（Public）** リポジトリを作成（例: `mirai-gikai-kuwana`）。AGPL-3.0 のためソースは公開が必須
2. このフォルダの `kuwana` ブランチを `main` として push
3. `web/src/config/external-links.ts` の `GITHUB_REPO` をそのリポジトリの URL に変更して push

## 2. Supabase

1. ダッシュボードで新規プロジェクトを作成（Region: Northeast Asia (Tokyo)）。DB パスワードを控える
2. 以下を控える
   - Project ref（URL の `https://<ref>.supabase.co` の `<ref>`）
   - Project URL
   - API Keys の **Publishable key** と **Secret key**
   - アカウントの Access Token（Account → Access Tokens）
3. 管理者ユーザーの作成（マイグレーション適用後に実施）
   - Authentication → Users → Add user（メール + パスワード）
   - SQL Editor で以下を実行
     ```sql
     UPDATE auth.users
     SET raw_app_meta_data = raw_app_meta_data || '{"roles": ["admin"]}'::jsonb
     WHERE email = '<作成したメールアドレス>';
     ```

## 3. Vercel AI Gateway

1. Vercel ダッシュボード → AI Gateway → API Keys で キーを発行（`AI_GATEWAY_API_KEY`）
2. AI Gateway のクレジットを追加（Anthropic モデル・Web 検索の利用料はここから引かれる）

AIチャットの設定（`web/src/features/chat/server/services/handle-chat-request.ts`）:

- モデル: Claude Haiku 4.5（`anthropic/claude-haiku-4.5`、入力 $1 / 出力 $5 per 1M tokens）
- Web 検索: Anthropic のサーバー側 Web 検索（`webSearch_20250305`）。1応答あたり最大3回、検索地域は三重県桑名市
- 利用上限は環境変数で設定（下記）。公開初期は小さめを推奨

## 4. Vercel プロジェクト（web と admin の2つ）

それぞれ「Add New → Project」で GitHub リポジトリをインポートし、**Root Directory** をそれぞれ `web` / `admin` に設定する。
Framework は Next.js、Install/Build コマンドは既定のままでよい（pnpm workspace を自動認識）。

### 環境変数

| 変数 | web | admin | 値 |
|---|:-:|:-:|---|
| `NEXT_PUBLIC_SUPABASE_URL` | ✓ | ✓ | Supabase の Project URL |
| `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` | ✓ | ✓ | Publishable key |
| `SUPABASE_URL` | ✓ | ✓ | Project URL（同上） |
| `SUPABASE_SECRET_KEY` | ✓ | ✓ | Secret key（**公開しない**） |
| `AI_GATEWAY_API_KEY` | ✓ | ✓ | AI Gateway のキー |
| `REVALIDATE_SECRET` | ✓ | ✓ | 任意のランダム文字列（web/admin で同じ値） |
| `NEXT_PUBLIC_WEB_URL` | ✓ | ✓ | 公開サイトの URL（例: `https://kuwana-gikai.vercel.app`） |
| `ADMIN_URL` | ✓ | ✓ | 管理画面の URL |
| `CHAT_DAILY_USER_COST_LIMIT_USD` | ✓ | | 1ユーザー1日あたりの上限（例: `0.5`） |
| `CHAT_DAILY_TOTAL_COST_LIMIT_USD` | ✓ | | サイト全体1日あたりの上限（例: `5`、未設定時 `50`） |
| `CHAT_MONTHLY_TOTAL_COST_LIMIT_USD` | ✓ | | サイト全体1か月あたりの上限（例: `50`、未設定時 `1000`） |
| `BASIC_AUTH_USER` / `BASIC_AUTH_PASSWORD` | 任意 | | 公開前の限定公開に使える |
| `LANGFUSE_*` | 任意 | 任意 | LLM 監視を使う場合のみ |

### Deploy Hook

`web/vercel.json`・`admin/vercel.json` は `main` への push で**直接はビルドしない**設定（本家と同じ）。
代わりに GitHub Actions がマイグレーション後に Deploy Hook を叩く。

各 Vercel プロジェクトの Settings → Git → Deploy Hooks で `main` 向けの Hook を作成し、URL を控える。

## 5. GitHub Actions の Secrets

リポジトリの Settings → Environments で `production` を作成し、以下の Secret を登録する（`deploy.yml` が参照）。

| Secret | 値 |
|---|---|
| `SUPABASE_ACCESS_TOKEN` | Supabase の Access Token |
| `SUPABASE_PROJECT_REF` | Project ref |
| `SUPABASE_DB_PASSWORD` | DB パスワード |
| `WEB_VERCEL_DEPLOY_HOOK_URL` | web の Deploy Hook URL |
| `ADMIN_VERCEL_DEPLOY_HOOK_URL` | admin の Deploy Hook URL |
| `ADMIN_AUTH_CALLBACK_URL` | `<ADMIN_URL>/api/auth/callback` |
| `SUPABASE_AUTH_EXTERNAL_GOOGLE_CLIENT_ID` / `_SECRET` | 管理画面の Google ログインを使う場合のみ |

登録後、`main` に push（または Actions から `deploy.yml` を再実行）すると、マイグレーション → web/admin のデプロイまで自動で行われる。

> worker（トピック分析）の `deploy_worker.yml` は GCP の Secret が無いと失敗する。使わない場合は
> Actions 画面でそのワークフローを Disable しておく。
> `integration_test.yml` など本家の CI も、必要に応じて有効/無効を判断する。
